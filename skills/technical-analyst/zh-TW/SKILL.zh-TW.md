## 概覽

本 skill 從圖表影像產出**次日方向預測**。它判讀日線圖的趨勢結構、關鍵價位、動能與波動度，然後對下一根日 K 給出三個互斥的結果，每個都附機率、預期價格區間與失效價位。

所有判斷只根據圖上看得到的內容，不受新聞、基本面或市場情緒影響。

### 「明日」的定義

預測標的是**下一根日 K 的收盤價，相對於最近一根已完成的日 K 收盤價**。分析前先確認交易時段的界線：

- **24/7 市場（加密貨幣）**：日 K 在 UTC 00:00 收盤，沒有跳空，下一根開盤即前一根收盤
- **有開收盤的市場（股票、指數、多數外匯）**：下一根日 K 涵蓋下一個交易時段，可能出現隔夜跳空，開盤價未必等於前收。這要當成獨立風險寫進預測

若從圖上無法判斷該標的的時段慣例，要說明並寫出所採用的假設。

### 主要級別與確認級別

- **日線（1D）** 是主要決策級別，所有結論都必須錨定在這裡
- **4 小時（4H）** 是可選的確認級別，只有在使用者真的提供 4H 圖時才使用
- **不得用週線圖預測次日**。若手上只有週線圖，說明並停止

## 核心原則

1. **純圖表分析** — 結論只能來自圖上看得到的技術資料
2. **有界的預測期間** — 每個判斷都只涵蓋一根日 K，不給無期限的目標價
3. **客觀評估** — 避免主觀偏誤，聚焦可觀察的型態與數值
4. **互斥的結果** — 三個情境必須窮盡且不重疊
5. **先有證據才有機率** — 機率的品質等於背後具名證據的品質
6. **校準過的謙遜** — 單日方向接近擲硬幣，信心水準要據此表達

## 分析流程

### 第零步：取得圖表

依序決定圖從哪裡來：

```
1. 使用者已提供圖片
     → 直接使用，跳過取圖。使用者提供的圖永遠優先
2. references/chart_sources.md 存在
     → 讀它並依其定義的程序抓圖。該檔記載頁面、幣種對應網址、
       抓圖參數、以及如何驗證抓圖成功
3. 兩者皆無
     → 請使用者提供日線圖，並說明圖上需要有什麼：
       可讀的價格軸、至少一個動能振盪指標、ATR
```

未指定幣種時，使用 `chart_sources.md` 裡定義的預設值，並說明你在預測哪個標的。

截圖必須寫到專案工作目錄以外的暫存目錄。

自動抓圖若未通過驗證，依 `chart_sources.md` 的「重試一次後停止」規則處理。**絕不分析半成品。**

> `SKILL.md` 本身只提到 `references/chart_sources.md` 這個檔名，**不含任何網址**——這是通用性的關鍵設計。

### 第一步：確認圖表可用性

不論圖從哪來，拿到後：

1. 確認有幾張圖、各自來源
2. 辨識標的，確認是日線圖（或註明哪幾張是 4H 確認用）
3. **盤點圖上實際看得到哪些指標、哪些缺席**
4. 記下使用者指定的重點
5. 逐一標的依序分析

若圖片無法判讀、指標被裁切、或太小看不出數值 → **直接說明並停止**，不得在部分可見的狀態下硬做。

### 第二步：載入分析框架

開始分析前先讀 `references/technical_analysis_framework.md`，內含：圖例數值判讀、趨勢分類、支撐阻力辨識、均線判讀、成交量、動能振盪指標、波動度與預期區間推導、型態辨識、情境與機率分配、次日預測的已知限制。

接著讀 `references/indicator_reading_rules.md`——單一指標的查表，含每個指標各自的**誤讀陷阱**。

> **兩者衝突時 framework 優先**：查表說「這根線代表什麼」，framework 說「這對明天值多少」。

### 第三步：逐張系統性分析

每一項都要記下一句話的證據。

| 子步驟 | 內容 |
|--------|------|
| 3.1 趨勢 | 方向、強度、持續時間、高低點結構 |
| 3.2 支撐阻力 | **最近的上下各一個價位最重要**，並以 ATR 為單位量測距離 |
| 3.3 均線 | 相對 20 / 50 / 200 **日**均線的位置、排列、斜率、交叉；特別注意距現價 1 ATR 內的均線 |
| 3.4 成交量 | 最新一日量能 vs **近 20 日均量**；量能不足的走勢是延續的弱證據 |
| 3.5 型態與價格行為 | **最近 1~3 根 K 棒權重最高**；收盤是否貼近當日高／低點 |
| 3.6 動能與趨勢指標 | RSI · MACD · Stochastic RSI · ROC · DMI/ADX · Aroon · Hull MA，以及 Supertrend · PSAR · Volatility Stop · Alligator · Fractals · Zig Zag · Linear Regression 等趨勢疊加 |
| 3.7 波動度與預期區間 | 讀 ATR(14) 推導 C ± 1 ATR 預期區間與 C ± 0.5 ATR 平盤區；並讀 Choppiness（評定趨勢讀數可信度）與 Historical Volatility |
| 3.8 綜合 | 整合上述，指出對「下一個交易時段」影響最大的因素與矛盾訊號 |

3.6 與 3.7 是原版沒有、為次日預測新增的兩節，也是次日方向的主要依據。

**圖上出現的指標，若列於 `indicator_reading_rules.md` 就依該檔判讀**；未列出的依 framework 的一般原則處理並說明。不要因為某指標不在上述七個標題內就略過——圖上可能載入比標題列舉更多的指標，每一個看得見的都是可用證據。圖上沒有的指標要明確標示為缺席，不得推測其數值。

若波動度嚴重壓縮、或圖表明顯呈區間震盪 → 預測應偏向 Flat，不要硬給方向。

### 第四步：產出次日預測

以最近一根日 K 收盤價 **C** 與 ATR 為基準，產出**三個互斥且窮盡**的情境：

| 情境 | 定義 |
|------|------|
| **Up 上漲** | 次日收盤 > C + 0.5 ATR |
| **Down 下跌** | 次日收盤 < C − 0.5 ATR |
| **Flat 區間** | 次日收盤落在 C ± 0.5 ATR 之內 |

機率加總必須恰為 100%。

每個情境必填四個欄位：

1. **機率** — 以 **5% 為級距**，證據撐不起更細的精度
2. **支持證據** — 具名的指標與讀數清單，例如「MACD 柱狀正值且連 3 根擴張」。沒有具名來源的敘述不算證據
3. **預期價格區間** — 由 ATR 與最近的支撐阻力推導
4. **失效價位** — 到了這個價就代表這個情境錯了

**機率紀律：**
- 從接近均等的先驗出發，只依實際列出的證據調整
- 具名證據少於兩項的情境不得超過 40%
- 純靠圖表判讀，任一情境不得超過 70%
- 平盤區相對近期日波動偏寬時，Flat 應占相當比重——窄幅整理是常見結果，不是逃避

### 第五步：產出報告

套用 `assets/analysis_template.md`，**結論先行**（Forecast Summary 放最前面）。

檔名慣例：`[SYMBOL]_forecast_[YYYY-MM-DD].md`，日期是**做預測的日期**，不是被預測的日期。

### 第六步：多標的逐一處理

一個標的完整跑完並存檔後，才換下一個。不批次處理。

## 硬規則

違反任何一條，這份報告即無效。

1. **只有看得到的才算數。** 數值不清、指標未顯示、解析度不足 → 該項標記為 `unreadable` 並排除在證據之外。**絕不**用市場知識、新聞、記憶中的價位或一般預期來補洞。

2. **每個判斷都要附證據。** 第三步的每一項都要有一句話描述觀察到的具體空間關係或數值，例如「收盤在 20 日均線上方 1.2%，且該均線向上」。寫不出具體證據 → 該項作廢，不得支持任何情境。

3. **機率要追溯得到證據。** 每個機率都必須對應到該情境列出的具名證據。不得產生假精確，只能用 5% 級距。

4. **要回報可讀性覆蓋率。** 說明有幾項可讀、幾項不可讀。若預測建立在少數可讀項目上，必須明顯標示。

5. **沒有圖就不預測。** 看不到或圖不堪用時，說明並停止。**空報告優於假報告。**

6. **不得超出預測期間。** 本 skill 只預測一根日 K，不得把目標價延伸到「下週」或「未來幾個月」。

7. **自動抓來的圖要先驗證再相信。** 抓圖可能 HTTP 成功卻沒有任何渲染出來的指標——空白窗格、圖例只有名稱沒有數值、或部分圖有 K 棒部分空白。**分析前先檢查圖片。** 空白窗格是「不可讀」而不是中性讀數；部分渲染就重抓一次，再失敗就停止。

8. **絕不對指標讀數計分或計票。** 不要統計偏多對偏空的數量、不要算百分比、不要導出綜合評級、不要呈現任何這類彙總。等權計數會讓**慢速結構型指標壓過真正主宰單一時段的快速動能讀數**。每個讀數是一項具名證據，仍受 framework 的類別規則約束——三個動能指標同向算**一個類別**，不是三項證據。

## 品質標準

**客觀性** — 只根據可觀察的圖表資料；不引入外部資訊；不使用「我認為」「我覺得」這類主觀措辭；訊號模糊時明確表達不確定性；三個結果一視同仁以避免確認偏誤。

**完整性** — 報告模板每一節都要填；支撐、阻力、預期區間、失效價位都要有具體價格；每個機率都要有具名證據；要寫出使用的 ATR 值與區間推導方式。

**清晰度** — 正確使用技術術語；結論先行再談分析；價位要具體不要含糊；三個情境保持互斥。

## 使用範例

**範例 1 — 單一標的**
使用者貼一張 BTC 日線圖問明天漲跌 → 確認是日線 → 讀 framework → 跑完七個分析面向 → 用 ATR(14) 推導預期區間 → 產出三情境（例如 Up 40% · Down 25% · Flat 35%），各附具名證據與失效價位 → 存成 `BTCUSDT_forecast_2026-08-30.md`

**範例 2 — 多標的**
BTC、ETH、Nasdaq 三張圖 → 註明 NDX 是有開收盤的市場、有跳空風險 → 逐一完整分析並各自存檔 → 全部完成後告知使用者

**範例 3 — 圖表資訊不足**
圖上沒有任何振盪指標、價格軸也讀不出來 → 指出 RSI / MACD / Stochastic / ATR 全部缺席、價格軸無法判讀 → 回報無法負責任地產出次日預測 → 說明需要什麼（可讀的價格軸 + 至少一個動能指標 + ATR）→ **不猜方向**
