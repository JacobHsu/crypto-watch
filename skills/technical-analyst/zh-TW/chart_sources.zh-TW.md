## 這個檔案的定位

**這是整個 skill 裡唯一與專案綁定的檔案。** 其餘三個執行檔（`SKILL.md`、`technical_analysis_framework.md`、`analysis_template.md`）完全不含專案網址、頁面名稱或指標配置。

**刪掉或換掉這一檔，skill 立刻回到通用狀態**——它會退回原本的行為：請使用者自行提供圖表。

## 要抓哪些頁

做次日預測時**兩頁都要抓**。兩者合起來才涵蓋框架需要的全部面向，缺一不可。

| 幣種 | 主要頁（動能＋波動度） | 補充頁（均線＋結構） |
|------|----------------------|-------------------|
| **BTC**（未指定時的預設） | `o/btc.html?t=1d` | `btc/1d.html` |
| **ETH** | `o/eth.html?t=1d` | `eth/1d.html` |
| 其他幣種 | `o/altcoin.html?s=<SYM>&t=1d` | 無 → 退而使用 `altcoin.html?s=<SYM>`，**只讀第 3 列**（由上到下為 1H / 4H / 1D） |

只有 `btc/`、`eth/` 有 2×2 細看頁。其他幣種的補充頁是 3×4 總覽，每張圖小很多——判讀不出來就標為 unreadable，不要硬看。

`?t=1d` **是必要的**。少了它頁面會退回 4H，對次日預測是錯誤的級別。

## 每一頁提供什麼

### `o/{symbol}.html?t=1d` — 四張圖，各含主圖 + 三個副圖窗格

| 組別 | 主圖 | 副圖（Pane） |
|------|------|-------------|
| 第一組 · 趨勢 | Supertrend | **MACD** · DMI/ADX · Aroon |
| 第二組 · 動能 | Hull MA (HMA) | **RSI** · **Stochastic RSI** · ROC |
| 第三組 · 波動 | Bollinger Bands | **ATR** · Choppiness Index · Historical Volatility |
| 第四組 · 量價 | VWMA 20 | OBV · MFI · Chaikin Money Flow |

這頁提供動能（框架第 5 節）與波動度（第 6 節）——**對一天的預測權重最高的兩個類別**。四張主圖都有成交量柱。

⚠️ **這頁沒有 MA 20/50，也沒有 EMA 20/50。**

### `{symbol}/1d.html` — 2×2 四張大圖

| 象限 | 指標 |
|------|------|
| 趨勢 | Multi-Time Period · Williams Fractals · Williams Alligator · Parabolic SAR |
| 通道 | Bollinger Bands · Keltner Channel · MA Cross · Volatility Stop |
| **均線** | **MA 20 / MA 50 · EMA 20 / EMA 50** · Donchian Channels |
| 趨勢／出場 | Zig Zag · Supertrend · Linear Regression · VWMA |

這頁提供均線類別（框架第 3 節），以及最清楚的價格標題——每張圖都印著 `開=<開> 高=<高> 低=<低> 收=<收> <漲跌> (<百分比>)`。

⚠️ 那個標題描述的是**進行中的 K 棒**。把 `收` 當成 C 是錯的——見下方「如何推導最近完成的收盤價」。

## 抓圖方式

TradingView 的 studies 是在頁面回報 network idle **之後**才非同步畫到 canvas 上的。任何只等 load 或 network-idle 事件的抓圖工具，拿到的都是有 K 棒但沒有指標、或副圖一片空白的半成品。**必須固定等 15 秒。**

用 Microlink，免費層不需要 API key。

```bash
curl -sS -G "https://api.microlink.io" \
  --data-urlencode "url=https://jacobhsu.github.io/crypto-watch/o/btc.html?t=1d" \
  -d "screenshot=true" \
  -d "waitForTimeout=15000" \
  -d "force=true" \
  -d "viewport.width=1920" \
  -d "viewport.height=1080" \
  -d "viewport.deviceScaleFactor=1" \
  -o response.json
```

回傳是 JSON，取 `data.screenshot.url`，把該 PNG 下載到暫存目錄，再讀取圖片檔。

### 參數

| 參數 | 值 | 說明 |
|------|-----|------|
| `waitForTimeout` | `15000` | **不可調低。** 這是指標能否畫完的關鍵 |
| `force` | `true` | **必要。** 繞過回應快取——見下 |
| `viewport.width` / `height` | `1920` / `1080` | 已驗證此尺寸可讀 |
| `viewport.deviceScaleFactor` | `1` | 已驗證足夠——圖例數值清晰。只有在某頁太密判讀不了時才調到 `2` |

### `force=true` 不是選配

**不帶它，API 會回快取的截圖。** 實測：同一個網址相隔兩小時的兩次抓取，回傳**位元組完全相同**的 PNG。加上 `force=true` 後才拿到真正即時的圖，價格、成交量、振盪指標讀數全都不同。

**快取是這個 skill 最糟的失敗模式**：圖渲染完美、通過下方每一項驗證、產出一份看起來很篤定的預測——而它建立在舊價格上，卻宣稱是最新的。**永遠帶 `force=true`。**

若相隔數分鐘的兩次抓取位元組相同，**不論如何都要懷疑是快取**。

### 等待時間的上限

`waitForTimeout` 不能無限調高。API 自身有約 29 秒的導航逾時，`waitForTimeout=25000` 會直接以 `EBRWSRTIMEOUT` 失敗，而不是等更久。

**已驗證可用的值：首次 15000、重試 20000。不要超過 20000。**

目標網址用 `-G --data-urlencode` 傳。手動處理跳脫字元很容易出錯，因為目標網址本身就含 `?` 和 `=`。

### 限制

- **截圖一律寫到 repo 以外的暫存目錄**，絕不落在專案工作目錄裡
- 免費層有每日配額，一次預測消耗兩次抓圖
- 抓圖是即時的：兩頁相隔數秒抓取，最新價可能略有差異。**以 `{symbol}/1d.html` 印出的收盤價為準**

## 分析前必須驗證抓圖成功

抓圖可能 HTTP 成功但內容無用。分析前先確認圖上真的有渲染出指標。

**最可靠的判準是圖例。** 渲染完成的圖會列出每個指標與其當前數值；沒渲染完的只剩 OHLC 標題，且常以省略號截斷。

| 檢查項 | 渲染正確 | 沒渲染 |
|--------|---------|--------|
| **圖例** | `RSI 14 close 70.81`、`ATR 14 RMA 2,197.29`、`MA 20 close 71,765.82` | 只有 `開=… 高=… 低=…` 後面接 `…`，沒有任何指標名稱或數值 |
| **副圖窗格** | `o/{symbol}.html?t=1d` 每張主圖下方有三個獨立窗格 | **窗格整個不存在、價格圖佔滿全高**——或存在但一片空白 |
| **主圖疊加** | Supertrend / HMA / 布林 / VWMA 的線畫在 K 棒上 | 只有光禿禿的 K 棒，沒有任何線 |
| **成交量** | 每張主圖底部有成交量柱 | 沒有成交量柱 |
| **所有圖** | 頁面上每張圖都畫出來了 | 有些圖有 K 棒、有些是空白灰塊 |

已觀察到**兩種不同的失敗型態**：**窗格整個消失**（等太短）與**窗格存在但空白**（部分渲染）。兩者都算失敗。

⚠️ 注意：兩種失敗情況下，**頁面周邊文字都會正常顯示**——右側說明欄是 DOM 文字不是 canvas。**它有內容不代表圖有畫出來。**

任一項失敗：

1. 用 `waitForTimeout=20000` 重抓一次（仍要帶 `force=true`）。**不要用更高的值**——會超過 API 自身的導航逾時而直接失敗
2. 再失敗就停止並回報缺了什麼——依 Hard Rule 5，**空報告優於假報告**。不得分析半成品

這條重試路徑不是假設。實測中補充頁曾出現：**所有指標線都正確畫出來了，但每個圖例都沒有數值**——`MA 20 close` 後面空白、`SAR 0.02 0.02 0.2` 沒有值、價格標題只剩最新價而沒有完整的開高低收。用 20000 重抓才填上。

⚠️ **「圖例只有名稱、沒有數值」是這些頁面最常見的部分渲染型態**，而且很容易漏掉——因為圖表其他部分看起來完全正常。

## 從這些圖讀數值

指標圖例是 canvas 的一部分，在上述設定下清晰可讀。**要引用數字。** 驗證抓圖時確認可讀的值：

- `o/btc.html?t=1d` — `MACD 12 26 close 9 501.42`、`RSI 14 close 70.81`、`Stoch RSI 3 3 14 14 close 61.64 72.59`、`ATR 14 RMA 2,197.29`、`CHOP 14 0 29.76`、`HV 10 48.10`、`MFI 14 79.08`、`OBV −1.17M`、`CMF 20 0.27`、`DMI 14 14 42.8175 38.2621 11.6689`、`Aroon 14 85.71% 0.00%`
- `btc/1d.html` — 每張圖標題的 `開/高/低/收`、`MA 20 close 71,765.82`、`MA 50 close 67,331.59`、`EMA 20 close 73,605.51`、`EMA 50 close 69,361.73`、`BB 20 close 2 ...`、`DC 20 0 ...`、`SAR 0.02 0.02 0.2 74,811.22`

**引用精確圖例數值的證據，強度高於描述線的位置。** 只要讀得到就用數字。

### 如何推導最近完成的收盤價 — 這段要看仔細

圖表標題印的是**進行中的 K 棒**，不是最近完成的日 K：

```
開=78,230.00  高=78,330.00  低=77,994.02  收=78,070.57  −159.43 (−0.20%)
```

這裡的 `收` 是一根**還沒結束**的 K 棒的當前價。**把它當成 C 是錯的。**

這些是 24/7 市場、沒有跳空，所以**當前 K 棒的開盤價就是最近完成的日收盤價**：

```
C = 開 = 78,230.00
```

用之前先驗算，印出來的漲跌必須對得上：

```
收 − 開 = 78,070.57 − 78,230.00 = −159.43   ✓ 與標題相符
```

對不上就代表標題讀錯了，**要說明而不是猜**。

**對預測標的的影響。** 被預測的那根 K 棒已經走了一部分。報告裡要寫明：已經走掉的幅度（本例 −0.20%，即低於 C 0.07 ATR），以及「所預測的時段有一部分已經發生」。這不是資料缺陷，是讀者必須知道的事實。

## 這個來源已知的缺口

以下兩頁都沒有。除非另有說明，**標為不可讀，不要用估計值代替**。

| 缺口 | 後果 |
|------|------|
| **沒有 200 日均線** | 框架第 3 節的長期參考不存在。只報 20 日與 50 日，並註明缺漏 |
| **沒有 20 日均量的數值** | 框架第 4 節要求「最新一日量能 vs 近 20 日均量」。圖上只有原始成交量柱，這個比較**只能目視對照鄰近的柱子**。這是這些圖產出的**證據中最弱的一項**——要標明是目視估計，且不得讓它單獨撐起任何情境 |
| **DMI 圖例沒有標欄位** | 圖例只有三個裸數字，例如 `DMI 14 14 42.8175 38.2621 11.6689`。依標準慣例讀成 ADX / +DI / −DI，並在報告中寫明這個假設 |

## 時間級別

這些頁面支援 15m / 1h / 4h / 1d。本 skill 預測的是下一根**日** K，所以一律用 `?t=1d` 與 `1d.html` 細看頁。**同一份預測內不得混用不同級別。**
