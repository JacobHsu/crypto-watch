# Symbol Calibration Notes

Optional. This file exists only for symbols that have an independent empirical backtest behind them. If the
instrument being forecast is not covered below, skip this file entirely and fall back to the generic treatment
in `technical_analysis_framework.md` and `indicator_reading_rules.md`.

Currently covers: **BTC, ETH**.

## What this is

A companion project (`py-tvscreener`) reads TradingView data programmatically and ran a real backtest: for each
technical indicator reading, it measured the actual win rate of the next 24 hours moving in the expected
direction, against a baseline of that symbol's unconditional odds of going up over the same window. The
difference (win rate − baseline) is "edge" — the source report calls it `docs/indicator-backtest/README.md`,
generated by `scripts/backtest_indicator_accuracy.py`.

This file distills that report into the two symbols this skill actually forecasts.

## How to use this

- Read this file in Step 2, alongside `technical_analysis_framework.md` and `indicator_reading_rules.md`, when
  the instrument being forecast is BTC or ETH.
- This does **not** authorize tallying or scoring (Hard Rule 8 in `SKILL.md` still applies in full). It only
  tells you which named-evidence categories deserve more or less weight when judging the evidence-count
  thresholds in framework §8 — a category flagged "empirically weaker/negative" below should not, by itself,
  justify moving a probability away from 50/50, even if it nominally satisfies the generic category-count rule.
- `indicator_reading_rules.md` still governs what a reading *is*. This file governs how much a *correct* reading
  is actually worth for this specific symbol.

## Horizon and resolution caveat — read before using any number below

The source backtest reads **1-hour-interval** indicator values and measures the next **24 hours** forward. This
skill reads **daily-interval** indicator values and forecasts the **next daily candle** (also ~24h for a 24/7
crypto market, so the horizon lines up, but the indicator's own timeframe resolution does not). Treat every
figure below as a **directional calibration signal** — which category of evidence has actually worked versus
which has not for this symbol — not as a literal probability to transplant onto a different indicator
resolution. The underlying sample is also explicitly bull-biased (2026-02 onward) and has not been tested
through a bear market or a sharp drawdown.

## BTC

### Empirically stronger evidence (weight these more)

| Reading | Direction | Edge |
|---|---|---|
| Ultimate Oscillator > 70 (overbought) | Bear (predicts down) | **+16.6pp** — strongest single signal in the whole report |
| 射擊之星 / Shooting Star candle | Bear | +8.9pp |
| MFI > 80 (overbought) | Bear | +6.4pp |
| RSI(14) > 70 (overbought) | Bear | +5.2pp |
| 倒錘形 / Inverted Hammer candle | Bull | +4.6pp |

**Asymmetry to note**: the oversold/Bull mirror of these readings does **not** work for BTC. RSI<30, MFI<20, and
Ultimate Oscillator<30 all score near-zero to clearly negative (Ultimate Oscillator Bull: −9.8pp). For BTC
specifically, "oversold" should not be read as "likely to bounce" — only the overbought→pullback direction has
real edge.

### Empirically weaker/negative evidence (do not let these carry a probability alone)

ADX+DI direction, Aroon dominance, Parabolic SAR side, MA/Technical Rating, and nearly all SMA/EMA crosses and
orderings — all sit at ~0 to slightly negative edge for BTC. Notably, the **ADX+Aroon+SAR three-way alignment**
that this skill's Confluence Checks table treats as reinforcing evidence is only +0.9pp (Bull) / +1.3pp (Bear)
for BTC — essentially noise, not the mutually-confirming signal naive confluence reasoning would suggest.

## ETH

### Empirically stronger evidence (weight these more)

| Reading | Direction | Edge |
|---|---|---|
| MFI > 80 (overbought) | Bear | +13.1pp |
| RSI(14) > 70 (overbought), while ADX > 20 | Bear | +13pp |
| RSI(14) > 70 (overbought) | Bear | +12.4pp |
| RSI(14) < 30 (oversold), while ADX > 20 | Bull | +7.8pp |
| Stochastic %K < 20 / > 80 | Bear | +7.4pp |
| CCI(20) < −100 / > 100 (extreme) | Bear | +6.7pp |
| RSI(14) < 30 (oversold) | Bull | +6.5pp |

Unlike BTC, **RSI extremes work in both directions for ETH** — oversold genuinely does predict a bounce here, not
just overbought predicting a pullback.

### Empirically weaker/negative evidence (do not let these carry a probability alone)

**ADX bullish direction (+DI > −DI, ADX ≥ 25) is actively harmful for ETH: edge −9.5pp — worse than a coin
flip.** This is the single strongest negative finding in the whole report; treat an ADX-confirmed uptrend
reading for ETH with real skepticism rather than as confirmation. Also negative for ETH: MA/Technical Rating,
most SMA/EMA crosses, Aroon (negative in both directions), and — contrary to textbook expectation — the 空頭吞噬
/ Bearish Engulfing candle (−5.7pp).

## Best single confluence for both symbols

**RSI(14) > 70 AND MFI > 80 at the same time** (both simultaneously overbought) is the report's best overall
performer: **+10.9pp for BTC, +15.3pp for ETH**, both Bear direction. See the "RSI × MFI dual-extreme" row added
to `indicator_reading_rules.md`'s Confluence Checks table. The oversold mirror (RSI<30 AND MFI<20, predicting a
bounce) is unreliable for BTC (−6.2pp) but moderately useful for ETH (+4.4pp) — the same BTC/ETH asymmetry as the
single-indicator readings above.

## Provenance and drift

Distilled from `docs/indicator-backtest/README.md` §3.1 (BTC) and §3.2 (ETH) in the `py-tvscreener` repo,
generated by `scripts/backtest_indicator_accuracy.py`. That report is regenerated whenever the underlying script
is rerun against more accumulated history — **this file will drift and cannot self-update.** Re-check by reading
the current version of that report and diffing the "高可靠" (high reliability) and "負向" (negative) sections
against the tables above, especially after the sample eventually covers a bear market or a sharp drawdown, which
the source report explicitly flags as untested.
